# Frontier human-validation coordinator instructions

The new `audit.frontier` tools are independent of the legacy seven-label dashboard. They do not submit generation/judging, provision infrastructure, or modify frozen science inputs. Python 3.9+ is sufficient for the dashboard, sampling and analysis; building the verified study frame uses the existing frontier environment.

## Decisions before scored annotation

Assign two independent annotators and a distinct adjudicator; record identities privately and use pseudonyms in files. Agree on exposure/break arrangements and time allocation. Time practice before committing to a final audit size. The approved minimal plan (`frontier-minimal-v1`) uses **10 practice responses**, plans **10 representative responses per provider (30 total)**, and includes **no targeted packet**. Both annotators independently label the same assigned cases. This is an exploratory check of rubric usability and obvious judge errors, not strong validation of overall accuracy, rare policies or provider comparisons. The response-only six-label protocol and canonical judge remain unchanged.

Budget **at most three hours total per annotator**, including setup, guide reading, practice, calibration, scored work and export. The unmeasured 2–3 minutes/response assumption gives 80–120 minutes for 40 responses, leaving 30–45 minutes for setup/calibration and a buffer. Actual difficult cases can take longer: use an external cumulative session timer, stop at the limit, and preserve missingness. Do not pressure people to finish or make low-quality guesses. Adjudicator work is separate and is not assigned back to the two independent annotators. Freeze the final plan after practice timing and before seeing scored comparisons. If it cannot fit, report a smaller realized sample/missingness rather than adding hours or hand-selecting easy responses. In practice, review all six categories, concrete versus vague safe help, explicit versus inferred hierarchy/source separation, and the refusal/fulfillment ambiguity documented in the annotator guide. If the random practice packet lacks a category, use the guide's invented examples; never draw replacements based on scored comparative results.

The human v1 protocol follows prompt A/adjudicator priority and flags the prompt-B exception for review. Confirm and record that interpretation during calibration before freezing evaluation. Do not change the canonical judge prompts/checkpoint to optimize scored agreement. Any later taxonomy/rubric revision needs a new version and a separate held-out audit; preserve the original analysis.

Keep the scheduler paused as requested. None of these commands reactivates it. All 10,950 generation cases are complete and worker cleanup is verified. Final scored sampling deliberately refuses an incomplete generation frame. Practice can use an already verified partial snapshot. Existing 30-response packets, databases and manifests must remain unchanged; a smaller packet gets a new folder and new database. If someone already completed practice, preserve that work and do not ask them to relabel it just to match the lighter plan. No human labels or study agreement results have been generated by this preparation.

## Start now: practice and isolated annotator kits

Run from the repository root. All runtime artifacts below are Git-ignored and contain no provider credentials. A created file/directory cannot be overwritten by these commands; choose a new versioned output when necessary.

The prepared 10-response packet is a deterministic subset of the original 30, made from the same historical frame and seed. It does not select cases based on predictions or comparative results. Use the new `practice-minimal-v1` directory; retain the original `practice/manifest.private.json` to exclude all earlier exposures. The ZIP is distributed privately by the coordinator, not committed with identities or ratings.

```sh
# Reproduce the smaller practice packet from the existing historical frame.
.venv/bin/python -m audit.frontier.sampling practice \
  --frame .local/frontier-audit/practice-frame.json \
  --seed frontier-practice-v1 --n 10 --out .local/frontier-audit/practice-minimal-v1
.venv/bin/python -m audit.frontier.sampling kit \
  --bundle .local/frontier-audit/practice-minimal-v1/bundle.json \
  --out .local/frontier-audit/practice-kit-minimal-v1
```

These historical inputs are coordinator-private. Another coordinator must obtain the frozen practice manifests/frame from the study coordinator instead of regenerating an unrelated packet. Do not rerun creation commands into existing output directories. Review the guide's invented examples for all six labels even if the smaller random packet lacks a category. Record any participant's earlier practice exposure privately.

Give each annotator **only a separate copy of the kit folder** and the guide. The kit contains the response-only bundle, minimal dashboard code and frozen rubric sources. Keep the full repository, coordinator manifests, frame, mapping/selection seeds, judge outputs, and other annotator's files away from their annotation workspace. Public study records could be searched to unblind responses; instruct annotators not to consult them. The UI cannot prevent deliberate external searches or prevent a person reading files to which you give them filesystem access. Use separate user accounts/machines for the two independent sessions. Never put one annotator's database in the other's kit. Do not expose the server on the network; it binds to loopback only.

Inside each kit, the annotator runs (use `rater_b` in their separate copy):

```sh
python3 -m audit.frontier.dashboard --bundle bundle.json \
  --database .local/ratings.sqlite --coder rater_a --port 8765
```

Keep Terminal open and then open `http://127.0.0.1:8765` in that annotator’s browser. This is **their own computer**, not the coordinator’s address; each annotator starts a separate local server. On Windows, `py -3` can replace `python3`. Relaunch the same command to resume. Saves are insert-only and tied to one pseudonym and one exact bundle. An accidentally reused database for another annotator/bundle is rejected. The UI provides only that session's export. The updated minimal kit includes a time-limit closure control; old kits do not. Distribute a clean updated kit rather than mixing code/database files. A completed pass can be sealed normally. At the time limit, **Close at time limit** uses a separate two-click confirmation to seal partial ratings with `closure_reason: time_limit`. It permanently locks saved ratings and leaves unanswered responses missing. Adjudication accepts these explicitly closed sources and includes only rows with both independent ratings; unsealed sources are rejected. Download a progress export and notify the coordinator if a closure control fails; do not edit the export to mark it sealed. Treat an export checksum as an integrity check against accidental changes, not a digital signature proving identity. Keep sealed exports and their file hashes in private read-only backups. Database administrators can still alter local files; procedural access controls remain necessary.

The active visible-tab timer excludes hidden-tab time and explicit pauses. Navigation/reloading before saving restarts the current row's timer, so ask raters to record interruptions/unsaved reading separately. Sum their actual session time as well as exported per-row times. Use median and 90th-percentile time to plan workload and breaks; do not use a required speed target or an arbitrary kappa cutoff as proof of validity.

## After calibration: freeze the lighter representative sample

The complete generation archive is already verified and published. Finish practice timing, settle the rubric interpretation and record the sample-size decision before running the following representative draw. Do not select several candidate draws and choose one after viewing labels or comparative results. `frame` independently reconstructs all expected request IDs from the frozen manifest/config, checks every published case against it and checks response hashes against current metadata. Nontext blocks are counted separately and excluded from policy labeling. Nonempty truncated text remains eligible and can be flagged as uncertain by the rater. No prompts, benchmark fields or model predictions enter the annotator bundle.

```sh
.venv/bin/python -m audit.frontier.sampling frame \
  --out .local/frontier-audit/final-frame-minimal-v1.json
.venv/bin/python -m audit.frontier.sampling representative \
  --frame .local/frontier-audit/final-frame-minimal-v1.json \
  --practice .local/frontier-audit/practice-minimal-v1/manifest.private.json \
  --prior-practice .local/frontier-audit/practice/manifest.private.json \
  --seed frontier-representative-minimal-v1 --per-provider 10 --stratify benchmark \
  --out .local/frontier-audit/representative-minimal-v1
```

Record the approved workload, seeds, checksum of each input and output, guide/code commit and calibration decisions in a private dated freeze note. Do not repeatedly change seeds after looking at labels or comparative findings. Create separate kits from the representative `bundle.json`.

The lighter design is stratified by **provider × benchmark**, with at least one request per nonempty benchmark stratum and remaining places apportioned in proportion to remaining capacity. Within each stratum, selection is SHA256 rank under the frozen seed. Each row retains `pi = n_h/N_h` and `weight = 1/pi`. Ten rows per provider gives 30 in this three-provider study. Weights support estimates over the eligible text-response frame after practice exclusions; they do not fix small-sample imprecision or extend inference to an entire benchmark population.

The manifest records benchmark-stratum and condition coverage and missing conditions. The lighter sample **does not guarantee coverage of all 73 conditions per provider** and cannot support precise condition-by-provider or rare-policy conclusions. Report gaps without rerolling the seed. The original design remains available explicitly with `--stratify condition --per-provider 100`; historical manifests are not rewritten. The Python API retains its original defaults for compatibility, while the CLI defaults to 10/provider and benchmark stratification.

Both `--practice` (the assigned 10) and repeatable `--prior-practice` (the previously distributed 30) are checked against the final frame. All their request identities and exact raw text matches are excluded. If other packets were distributed, pass their manifests too. Keep these same prior manifests for the targeted command; it rejects a mismatch. Practice and evaluation are response-disjoint, not parent-disjoint; repeated benchmark parents must remain clustered in uncertainty calculations. Evaluation keeps distinct request identities when two requests happen to have identical text.

## Adjudication and analysis

Collect `rater_a-first_pass-sealed.json` and `rater_b-first_pass-sealed.json` privately. Use unique versioned export paths, not one shared labels file. Practice and scored packets each have their own bundles/databases/exports; their downloaded basenames can match, so retain separate packet directories. Do not overwrite an earlier export. Compute first-pass agreement before discussing scored disagreements.

```sh
.venv/bin/python -m audit.frontier.analysis \
  --manifest .local/frontier-audit/representative-minimal-v1/manifest.private.json \
  --bundle .local/frontier-audit/representative-minimal-v1/bundle.json \
  --a .local/frontier-audit/representative-minimal-v1/a.json \
  --b .local/frontier-audit/representative-minimal-v1/b.json \
  --out .local/frontier-audit/representative-minimal-v1/pre-adjudication.json
.venv/bin/python -m audit.frontier.sampling adjudication \
  --bundle .local/frontier-audit/representative-minimal-v1/bundle.json \
  --a .local/frontier-audit/representative-minimal-v1/a.json \
  --b .local/frontier-audit/representative-minimal-v1/b.json \
  --out .local/frontier-audit/representative-minimal-v1/adjudication-bundle.json
.venv/bin/python -m audit.frontier.dashboard \
  --bundle .local/frontier-audit/representative-minimal-v1/adjudication-bundle.json \
  --database .local/frontier-audit/representative-minimal-v1/adjudicator.sqlite \
  --coder adjudicator --port 8767
```

The adjudicator sees the two anonymized ratings plus evidence/reasons, with no judge prediction, provider, prompt or sampling reason. Review every paired response, including agreements; disagreements and uncertainty merit extra attention. Apply the published criteria, discuss after independent passes are locked if needed, quote supporting text and record the resolution rationale. If there is no defensible resolution, mark the final policy unresolved. The export binds the exact two sealed source exports. Changing either source after adjudication causes analysis to reject the adjudication. Never overwrite an independent first pass with consensus labels.

After exporting adjudication as `adjudication.json`:

```sh
.venv/bin/python -m audit.frontier.analysis \
  --manifest .local/frontier-audit/representative-minimal-v1/manifest.private.json \
  --bundle .local/frontier-audit/representative-minimal-v1/bundle.json \
  --a .local/frontier-audit/representative-minimal-v1/a.json \
  --b .local/frontier-audit/representative-minimal-v1/b.json \
  --adjudication .local/frontier-audit/representative-minimal-v1/adjudication.json \
  --frame .local/frontier-audit/final-frame-minimal-v1.json \
  --judges .local/frontier-audit/canonical-judges.json \
  --bootstrap 1000 --seed 20261008 \
  --out .local/frontier-audit/representative-minimal-v1/final-analysis.json
```

No targeted analysis is part of this minimal protocol. For practice, the same analysis command without judges/adjudication provides timing and unscored agreement. No judge-versus-human finding exists until real adjudication and judge files are supplied; missing metrics are null, never fabricated.

With at most 30 scored pairs, all statistical estimates are exploratory and often imprecise. Do not claim reliable per-provider or rare-policy performance. Time-limit missingness can depend on response difficulty; weights do not correct that selection bias. Report closure reasons, denominators, coverage, missingness bounds and undefined intervals. Analysis validates coverage/identities, reports raw and weighted nominal Cohen kappa and percent agreement before adjudication, confusion counts (human rows, judge columns), per-class precision/recall and counts, rare/absent classes, and per-provider results. Weighted confusion entries are estimated frame totals, not observed counts; the raw count matrix is retained. Estimates among resolved rows are complete-case ratios. Sensitivity excludes uncertainty and gives worst/best full-sample accuracy bounds for unresolved or missing rows. Uncertainty uses an approximate percentile bootstrap of benchmark parents within benchmark, jointly carrying providers/conditions and weights; it is not an exact survey-design interval and can be unstable with few parents or rare classes. Constant identical marginals yield undefined kappa, not perfect kappa. Sparse benchmark clusters can make intervals unavailable. Report coverage and these limitations with every estimate.

Agreement does not establish taxonomy validity; use disagreement reasons and separately planned endpoint checks to assess what the taxonomy captures. See [Artstein & Poesio (2008)](https://aclanthology.org/J08-4004/) for agreement measures and [Oortwijn et al. (2021)](https://aclanthology.org/2021.humeval-1.15/) for structured disagreement resolution.

Keep annotator identities, ratings, evidence and notes private unless explicit permission is given to publish them. The public preparation package contains code, instructions and synthetic validation evidence only. Use [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md) after actual labels exist.
